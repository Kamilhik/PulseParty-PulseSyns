# PulseParty

Автор: [Kamilhik](https://github.com/Kamilhik). Репозиторий: [PulseParty-PulseSyns](https://github.com/Kamilhik/PulseParty-PulseSyns).

**Разработка с использованием ИИ:** да, при реализации и проверках использовался OpenAI Codex. Аддон использует официальный WebHost SDK и структуру официального [шаблона PulseSync](https://github.com/PulseSync-LLC/PulseSync-ExampleAddon). Это сторонний аддон, не официальный продукт PulseSync или Яндекса.

Список изменений: [CHANGELOG.md](addon/CHANGELOG.md). Готовые архивы: [GitHub Releases](https://github.com/Kamilhik/PulseParty-PulseSyns/releases).

Закрытые комнаты совместного прослушивания для **обычного PulseSync** и Яндекс Музыки. Кнопка «Слушать вместе» открывает диалог поверх плеера; ведущий выбирает музыку и передаёт пульт участникам.

Версия 0.3.0 использует общий HTTPS-сервис. **На компьютерах участников нужны только стандартный PulseSync и аддон.** Не требуется заменять `app.asar`, устанавливать native-модуль или запускать companion. Сервис один на компанию друзей; его можно разместить на Cloudflare Workers Free с SQLite-backed Durable Object и адресом `workers.dev`, без покупки VPS и домена.

**Сервис опубликован:** https://pulseparty.pulseparty.workers.dev. Через публичный HTTPS прошла проверка трёх HTTP-клиентов, long polling, паузы, двух передач управления, прав и отзыва приглашений. Аддон с этим адресом установлен в обычный PulseSync; в настоящей Яндекс Музыке подтверждены открытая комната и приглашение. Воспроизведение на двух настоящих аккаунтах/компьютерах остаётся непроверенным.

Готовый `dist/PulseParty-addon.zip` уже настроен на этот сервис. Инструкции ниже нужны для пересборки или своего размещения. Если собирать исходники без `.env` и адреса, панель покажет «Сервис комнат ещё не настроен» и не отправит запросы на localhost.

## Установка готового аддона

1. Откройте [последний релиз](https://github.com/Kamilhik/PulseParty-PulseSyns/releases/latest) и скачайте `PulseParty-0.3.0.pext`.
2. Откройте файл через PulseSync или перетащите `.pext` в его окно, затем включите аддон.
3. В Яндекс Музыке нажмите «Слушать вместе», создайте комнату и передайте другу приглашение. Другу нужна та же версия аддона.

В качестве альтернативы скачайте ZIP аддона и распакуйте **его содержимое** в `%APPDATA%\PulseSync\addons\pulseparty`, сохранив свои настройки. В этой папке должны лежать `metadata.json`, `script.js`, `script.css`, а не исходники проекта. ZIP и PEXT релиза содержат одну и ту же сборку. Контрольные суммы — в `SHA256SUMS.txt` релиза.

Для участников готовая сборка уже подключена к общему сервису. Следующий раздел нужен только для самостоятельного размещения и разработки.

## Бесплатное размещение

Условия и команды: [docs/CLOUDFLARE.md](docs/CLOUDFLARE.md).

```powershell
npm ci
npm run login:cloudflare
npm run check:cloudflare
npm run deploy:cloudflare
```

Затем возьмите **реальный** HTTPS-адрес из результата публикации. Конфигуратор проверит `/v1/health` и сохранит адрес в локальном `.env`:

```powershell
node scripts/set-relay.mjs <адрес-из-Cloudflare>
npm run build
```

Скопируйте содержимое `dist/pulseparty` в `%APPDATA%\PulseSync\addons\pulseparty` с сохранением пользовательского `pulsesync.settings.json`. Перезагрузите аддон в PulseSync. Друзьям передайте `dist/PulseParty-addon.zip` из этой же сборки: в ней совпадают адрес сервиса и разрешения `allowedUrls`.

Обычная проверка/обновление мода PulseSync не требует повторной установки native-части: её в этом варианте нет. Совместимость SDK при обновлениях самого PulseSync всё равно нужно проверять.

## Как слушать

1. Откройте «Слушать вместе» и создайте комнату. Имя подставляется из профиля Яндекс Музыки автоматически (при недоступном публичном имени — логин SDK).
2. Выбирайте музыку в обычном плеере Яндекс Музыки.
3. Создайте приглашение и вручную отправьте другу ссылку или код.
4. Друг вставляет ссылку/код в панель «Слушать вместе» и нажимает «Войти по приглашению».
5. Передайте управление через кнопку рядом с участником. Владелец комнаты и ведущий — отдельные роли.

В «Настройках комнаты» владелец выбирает, кому доступны кнопки «Назад» и «Далее»: только владельцу или всем участникам. Они переключают очередь текущего ведущего; передача пульта остаётся отдельным действием. Права проверяет сервер. Повтор запроса не должен повторно перелистывать трек; команды от прежнего ведущего после передачи пульта отклоняются.

Синхронизация не показывает всплывающих уведомлений при возврате трека/паузы/позиции. Изменения состояния будят последовательный цикл синхронизации через SDK-события и long polling, резервная проверка — 200 мс. Нативная загрузка трека и задержка сети по-прежнему влияют на фактическое начало звука.

HTTPS-страница приглашения проверяет срок действия и позволяет скопировать код. Она не обещает автоматический запуск приложения: стандартный аддон не регистрирует собственный протокол ОС.

Каждый слушает через свой аккаунт и подписку. Передаются метаданные и состояние, без аудио, cookies и токенов Яндекса. Участники следуют за текущим треком ведущего, включая «Мою волну»; персональные очереди не копируются. Скорость 1×, громкость независима.

## Discord

Стандартный SDK не предоставляет Discord IPC и callback принятия нативного приглашения. Поэтому **нативные приглашения PulseParty через активность Discord в этой сборке недоступны**. Обычный статус прослушивания можно включить средствами самого PulseSync. Приглашение PulseParty отправляйте как обычную ссылку/код.

Исторические исходники native iroh, Discord RPC и установщика сохранены отдельно для разработки; они не являются зависимостью стандартного аддона. Их описание — [docs/EMBEDDED-LEGACY.md](docs/EMBEDDED-LEGACY.md). Не запускайте `install-host.mjs` для текущего варианта.

## Проверки и сборки

```powershell
npm run check
npm test
npm run check:cloudflare
# Два терминала для локальной проверки, не для установки участникам:
npm run dev:cloudflare
npm run test:cloudflare
```

`npm run build` создаёт `dist/PulseParty-addon.zip`, `dist/PulseParty-source.zip` и исторический архив native-части. Для обычного PulseSync нужен только ZIP аддона, настроенный на опубликованный сервис. Исходники и приватные значения `.env` не нужны участникам.

Состояние комнат хранится в памяти единственного Durable Object, обеспечивающего общую авторитетную историю. При его перезапуске/вытеснении или публикации новой версии комнаты могут завершиться; создайте новую и повторно пригласите друзей. Постоянного хранения комнат нет. Сервис не публикует каталог комнат. Запросы ограничены по размеру/частоте, роли и сессии проверяются на сервере.

Подробнее: [архитектура](docs/ARCHITECTURE.md), [результаты проверок](docs/VERIFICATION.md), [проверка двух компьютеров](docs/MANUAL-TEST.md).
