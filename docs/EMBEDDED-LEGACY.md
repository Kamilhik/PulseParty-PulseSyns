# Исторический вариант с изменением PulseSync

Этот документ сохранён для исходников 0.1.x. По текущему требованию пользователя он **не используется**: основная сборка 0.2.0 работает с обычным PulseSync через общий HTTPS-сервис. Проверка мода в PulseSync заменяет изменённый app.asar, поэтому такой способ установки не подходит.

# PulseParty

Совместное прослушивание в PulseSync / Яндекс Музыке: закрытые комнаты, выбор ведущего, передача пульта и независимая локальная громкость.

**Основной режим после уточнения требований — встроенный iroh.** Комнаты и Discord работают внутри процесса модифицированной Яндекс Музыки. Отдельный companion, VPS, домен, Docker и самостоятельный сервер комнат для этого режима не нужны. В исходниках также сохранён необязательный вариант HTTP relay + companion из первоначального ТЗ.

**Граница готовности:** аддон и встроенная native-часть собраны для Windows x64. Автотесты используют три настоящих native iroh-узла, а браузерный сценарий — тестовые адаптеры плеера и Discord. Реальная установка модифицированного хоста, воспроизведение на двух аккаунтах и нативные Discord-приглашения ещё не проверены. Одного ZIP аддона недостаточно: стандартный SDK не предоставляет native iroh и Discord IPC; требуется прилагаемое минимальное расширение хоста. Установленное приложение автоматически не изменялось.

## Готовые файлы

- `dist/PulseParty-addon.zip` — аддон с `metadata.json`, `script.js`, `script.css`.
- `dist/PulseParty-host-Windows-x64.zip` — модуль для main-процесса PulseSync, включая Windows x64 native iroh. Это библиотека для хоста, а не отдельная программа.
- `dist/PulseParty-source.zip` — исходники, lockfile, тесты и документация без node_modules и приватной конфигурации.
- `dist/host/pulseparty/index.cjs` — точка входа встроенной части.
- `docs/VERIFICATION.md` — результаты и границы проверок.
- `docs/ARCHITECTURE.md` — протокол, роли, безопасность и исследованные API.
- `docs/MANUAL-TEST.md` — сценарий для двух настоящих компьютеров.

## Сборка

Node.js 22.12+ или новее; проверено на Node.js 26.11.1, PowerShell 7.6.9, Windows x64. Зависимости закреплены в `package.json` и `package-lock.json`.

```powershell
npm ci
npm test
npm run build
```

Для основного режима `.env` не требуется. Если создаёте его из `.env.example`, оставьте `PULSEPARTY_RELAY_URL=http://127.0.0.1:18787`. Здесь loopback — **внутренний интерфейс текущего процесса приложения**, а не адрес для подключения друзей. Между компьютерами работает iroh.

## Подключение к PulseSync

Для установленной **Яндекс Музыки 5.128.0 / PulseSync-mod 2.2.1 на Windows x64** добавлен локальный установщик с резервной копией. Он сохраняет все остальные файлы текущего приложения, меняя только точку подключения и добавляя модуль. Переподготовка нужна после обновления приложения.

```powershell
node scripts/install-host.mjs --prepare
# Полностью закройте Яндекс Музыку, включая значок в трее.
node scripts/install-host.mjs --apply
```

`--prepare` проверяет версию, собирает отдельный архив и сверяет хеши неизменённых файлов, не изменяя установленный архив. `--apply` отказывается работать при запущенном приложении, повторно проверяет исходный хеш и сохраняет резервную копию в `%LOCALAPPDATA%\PulseParty\backups`. Приложение после установки запускается пользователем. Скрипт не запускает Electron для проверок. Для других версий используйте подготовку исходников ниже.

Нужен исходный checkout [PulseSync-mod](https://github.com/PulseSync-LLC/PulseSync-mod). Адаптация проверена статически на commit `ca66618a0084e1d24815bf6ba2ca32560a32af02`. На других версиях сначала проверьте точку старта main-процесса. Не подменяйте `app.asar` случайной сборкой с GitHub.

1. Соберите этот проект.
2. Подготовьте **исходники мода**, указав их реальный путь:

```powershell
node scripts/prepare-host.mjs 'C:\path\to\PulseSync-mod'
```

Скрипт копирует `dist/host/pulseparty` в `src/main/lib/pulseparty` выбранного checkout, сохраняет `src/main/index.js.pulseparty-original` и добавляет один вызов после проверки единственного экземпляра:

```javascript
require('./lib/pulseparty/index.cjs').start({
    app: electron_1.app,
    BrowserWindow: electron_1.BrowserWindow,
    store: store_js_1,
});
```

3. Соберите и установите мод штатным способом **для вашей версии Яндекс Музыки**, согласно README и AGENTS.md его checkout. Скрипт подготовки не собирает и не меняет установленный `app.asar`.
4. Установите `dist/PulseParty-addon.zip` через локальную установку аддонов PulseSync либо откройте этот проект в редакторе аддонов. Включите PulseParty.
5. Перезапустите Яндекс Музыку. Рядом с плеером появится «Слушать вместе».

Статически обнаружены PulseSync 3.0.0-beta, Яндекс Музыка 5.124.1 и мод 2.0.4. В архиве установленного мода найдены нужные capabilities и методы плеера, но это **не проверка загрузки аддона**. Сборка основного мода поверх установленного приложения в этой задаче не выполнялась.

После обновления основного мода интеграцию нужно применить к его новым исходникам и пересобрать: изменения хоста не устанавливаются как обычный renderer-аддон.

Расширение слушает только `127.0.0.1:18787` внутри процесса приложения. Оно передаёт аддону случайную capability через `modSettings.pulseParty.bridgeToken`; ручного сопряжения в основном режиме нет. Не открывайте этот порт в маршрутизаторе.

Удаление: выключите аддон, восстановите исходный main из `.pulseparty-original`, удалите `src/main/lib/pulseparty` в checkout и соберите штатный мод. Протоколы `pulseparty` и `discord-<ваш Application ID>` регистрируются для приложения; при окончательном удалении их можно убрать из `HKCU\Software\Classes` после проверки команды, на которую они указывают. Не удаляйте регистрацию другого приложения.

## Как слушать

1. Нажмите «Слушать вместе», введите имя и создайте комнату.
2. Выберите музыку в обычном интерфейсе Яндекс Музыки.
3. Создайте приглашение и скопируйте ссылку `pulseparty://join#pp1.…` либо код `pp1.…`. Отправьте его другу вручную.
4. Друг открывает ссылку в установленном приложении или вставляет её в «Войти по приглашению».
5. Нажмите «Передать пульт» рядом с участником. Новый ведущий сначала принимает текущий трек комнаты, затем управляет музыкой через свой обычный плеер.

Некоторые мессенджеры не делают произвольные URI кликабельными. Код всегда можно вставить вручную. HTTPS-страница требует размещения статического сайта; в основном режиме хостинг не нужен и не предполагается существование выдуманного публичного URL.

Участники используют свои аккаунты и доступ к Яндекс Музыке. Аудио, cookies и OAuth-токены не передаются. «Моя волна» запускается только у ведущего: остальные следуют за его текущим треком. Очереди и персональные рекомендации не копируются. Поддерживается скорость 1×; выберите её в клиенте — SDK не предоставляет подтверждённого метода установки скорости.

## Discord без отдельной программы

Встроенная часть использует `@xhayper/discord-rpc@1.5.1` через Discord IPC — тот же вид транспорта используется самим PulseSync. Это **не Discord Social SDK**. Существующая публикация PulseSync не перехватывается и её настройки автоматически не изменяются.

1. Создайте собственное приложение в [Discord Developer Portal](https://discord.com/developers/applications). Скопируйте Application ID; не используйте ID Spotify или PulseSync. Бот и пользовательский Discord token не нужны.
2. При необходимости настройте Rich Presence / Art Assets / изображение приглашения в этом приложении. Название приложения — PulseParty.
3. В настройках PulseSync вручную отключите обычный Discord RPC.
4. В панели PulseParty раскройте Discord, введите Application ID, выберите `Listening` и нажмите «Подключить Discord». Отдельно включите «Показывать мою активность».
5. Владелец комнаты включает «Разрешить вход из профиля и приглашений Discord». Публикуется короткоживущий, проверяемый координатором секрет. При закрытом входе join secret отсутствует.
6. Для отправки откройте чат друга в Discord и используйте пункт приглашения приложения через «+» у сообщения, **если Discord показывает его для этого приложения**. Кнопка в аддоне объясняет этот шаг и сама сообщения не отправляет.

Обработчик `ACTIVITY_JOIN` регистрируется до подключения, подписка выполняется сразу после RPC handshake. Есть регистрация `discord-<Application ID>` для запуска приложения и `pulseparty://` для обычных ссылок. Принятое приглашение проверяется по iroh, сохраняется на 180 секунд, дедуплицируется и требует подтверждения в панели. Пользователь не покидает другую комнату автоматически.

**Нативный invite и холодный запуск через этот RPC-транспорт пока не сертифицированы реальным Discord.** Если подписка отклонена, код не публикует join secret и показывает, что доступны только статусы. Заполнение party/secret само по себе не считается доказательством работающего invite. Для несовместимого отображения Listening есть явный Playing в настройках; тип не меняется скрытно, подделки Spotify нет. URL-кнопка не выдаётся за нативное приглашение и в основном режиме не публикуется: собственного HTTPS-хостинга нет.

Официальный Social SDK `1.11.24259` исследован отдельно. Исходник `companion/native/` относится к необязательному первоначальному варианту; он не запускается и не требуется встроенному режиму. Его сборка требует получения SDK в Developer Portal и C++20/CMake; SDK/DLL здесь не подменены заглушкой и не включены в сборку.

## Работа сети и ограничения

- Iroh выбирает прямое QUIC-соединение, а при необходимости использует публичную инфраструктуру n0. Её не нужно разворачивать пользователю. Публичные relay предназначены для hobby/development, не имеют SLA, ограничивают трафик и могут требовать обновления iroh. Это зависимость от внешней инфраструктуры, а не обещание работы без каких-либо серверов в интернете. [Политика n0](https://docs.iroh.computer/iroh-services/relays/public).
- Данные комнаты зашифрованы между endpoint-ами. Прямые участники могут узнать IP друг друга; relay видит метаданные соединения.
- Координатор комнаты — устройство её создателя. Передача пульта и владения меняет права, но не переносит координатор. Создатель может выйти из участников после передачи владения, сохраняя приложение открытым. Если он закроет Яндекс Музыку или его приложение перезапустится, комната станет недоступна; создайте новую. Автоматической миграции координатора нет.
- Лидер меняется после grace period 20 секунд; владелец при этом остаётся прежним. Вернувшийся бывший ведущий не получает пульт автоматически.
- Порог коррекции по умолчанию 800 мс, cooldown 3000 мс. Они настраиваются в SDK-настройках аддона, применяются после его перезапуска. Это комфортная синхронизация, не семпловая точность.
- Готовая native-сборка — Windows x64. Для macOS/Linux нужно собрать пакет под свою платформу и включить соответствующий native iroh-пакет; бинарники и установка на этих ОС не проверены. На macOS основному приложению потребуются штатные настройки URL scheme в bundle.

## Проверки

```powershell
npm test
npm run check
npm run build
npm audit
node scripts/inspect-installed.mjs
```

Браузерный сценарий с тремя настоящими native iroh-узлами:

```powershell
npm run preview
# В другом терминале:
npx playwright install chromium
npm run test:ui
```

На этой машине сценарий выполнен в установленном Edge headless:

```powershell
$env:BROWSER_CHANNEL='msedge'
npm run test:ui
```

Плеер и Discord в браузерном стенде заменены явно обозначенными адаптерами, звук не воспроизводится. Сам iroh в этих проверках настоящий: отдельные endpoint-ы и QUIC-потоки, локальные адреса используются только в тестовом resolver. Тесты двух настоящих компьютеров и аккаунтов приведены в `docs/MANUAL-TEST.md`.

## Необязательный HTTP-вариант из первоначального ТЗ

Он сохранён для разработки и желающих использовать внешний координатор; по последнему уточнению **не является основным способом установки**. См. `docs/LEGACY-HTTP.md`. Docker, домен и companion относятся только к нему.
