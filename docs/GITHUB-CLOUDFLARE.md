# Cloudflare и GitHub

Рабочий сервис: https://pulseparty.pulseparty.workers.dev.

Адрес указан в `addon.config.mjs` как значение по умолчанию и одновременно используется в сетевых разрешениях аддона. Для сборки после `git clone` не нужен локальный `.env`. В репозитории находятся исходники Worker, `wrangler.jsonc`, SQLite-backed Durable Object migration и статические файлы страницы приглашения.

## Автодеплой сервера

Workflow `.github/workflows/cloudflare.yml` запускается при изменении серверных исходников, протокола, страницы приглашения, зависимостей или самого workflow в ветке `main`. Его можно запустить вручную через GitHub Actions → Deploy Cloudflare → Run workflow.

Перед публикацией выполняются установка закреплённых зависимостей, проверка типов и тесты. После публикации проверяется публичный `/v1/health`. Задачи выполняются последовательно, без отмены предыдущего деплоя.

В Settings → Secrets and variables → Actions используются:

- Variable `CLOUDFLARE_ACCOUNT_ID` — ID аккаунта владельца сервиса.
- Secret `CLOUDFLARE_API_TOKEN` — отдельный ключ Cloudflare с правом редактирования Workers Scripts, ограниченный аккаунтом/Worker `pulseparty` настолько узко, насколько позволяет Cloudflare. Для существующего Worker достаточно прав Editor; доступ к другим продуктам не нужен.
- Variable `CLOUDFLARE_DEPLOY_ENABLED=true` — включается после добавления ключа. Пока ключ не настроен, workflow не пытается выполнять публикацию.

Создать ключ можно на [странице API Tokens Cloudflare](https://dash.cloudflare.com/profile/api-tokens). Значение нужно поместить только в GitHub Actions Secret; пароль и ключ не передаются в чат и не записываются в исходники. Локальные OAuth/refresh-токены Wrangler в GitHub не копируются.

Ключ доступен только шагу проверки наличия и шагу деплоя; установка зависимостей и тесты его не получают. Автодеплой не запускается на коде из pull request стороннего автора. GitHub token самого workflow имеет только `contents: read`.

Сохранить файл workflow недостаточно для работающего автодеплоя: должен быть добавлен секрет и успешно завершён хотя бы один запуск Actions. До этого настройку нельзя считать подключённой.

Смена кода/перезапуск облачного объекта может завершить открытые комнаты. Аватарка и другие изменения только renderer-аддона не требуют публикации Worker.
